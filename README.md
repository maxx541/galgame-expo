# 口袋中的夏末號 — 線上週邊展示牆

一個給個人收藏用的線上展覽網站。展出立牌、掛畫、色紙、原畫集與各式限定特典。
純靜態前端 + 無伺服器架構，**完全免費**，不需要自己的主機。

```
index.html   展覽頁（給所有人看）
admin.html   上傳後台（要密碼）
```

---

## 現在就能看

不用設定任何東西，直接起一個本機伺服器就能看到完整效果 ——
站上會有 **108 件自動產生的佔位展品**，版面、篩選、搜尋、燈箱全部都能操作。

```bash
cd "D:\claude工作區\Galgame週邊線上展覽"
npx serve .
```

然後開 <http://localhost:3000>。

後台預設密碼：`sakura2024`（正式上線前**務必**更換，方法見下方）。

## 設計方向

**「黃昏的美術社倉庫」** —— 用 Galgame 的視覺語言，包裝一個以商品照片為主角的展場。

借用的 Galgame 元素：

| 元素 | 用在哪 |
|---|---|
| ADV 對話框（テキストボックス）+ 名前欄 | 燈箱下方的展品說明 |
| 選択肢（選項選單）hover 時浮出的 `▶` 游標 | 分類篩選按鈕 |
| 明朝體標題 + 日文小字標註 | 站名、章節標題 |
| 等待點擊的閃爍 `▼` | 對話框右下角 |
| 晝 / 夜兩套配色 | 主題切換（右上角 ☀/☾） |
| 櫻花飄落 | 可選特效，**預設關閉** |

### 最高原則：不花俏

這是展覽，主角是週邊商品的照片，不是介面本身。所以：

- **文字一律在圖片外側**。卡片說明放在圖片下方，任何時候都不會有東西蓋住商品
- **圖片不裁切**。masonry 版面讓直式、橫式、方形的週邊照各自保持原比例
- **裝飾壓到很淡**。背景的 bokeh 光斑只有 16% 不透明度，櫻花預設關閉，標題沒有流光動畫
- **hover 不放大圖片**。放大會讓細節變糊，只做 3px 的輕微浮起
- **角度有刻度，不是滿圓 pill**。`--radius-sm`(8px) / `--radius`(14px) / `--radius-lg`(22px)
  三級，真正的圓形只留給圖示鈕（`.btn--icon`）、燈箱箭頭、回頂端鈕這種傳統上就是圓的
  介面元件。分類 chips、卡片角標、按鈕這些文字容器原本全部用滿圓 pill，看起來很像
  隨手套模板的 AI 生成介面，已經改回刻度

## 手機版

週邊展覽有很大機率是在手機上被滑到的，所以手機版不是縮小版，是重新排過的：

- **2 欄 masonry**（< 360px 才退回單欄）—— 一眼掃過較多商品，又還看得清楚
- 右上角可切換 **單欄大圖模式**，想細看時用
- header 壓到 58px，「上傳」按鈕只留圖示
- 篩選 chips 橫向捲動，可捲出左右留白
- 燈箱用 `100dvh`（iOS 網址列收合時不會切到圖）、左右滑動換圖、下滑關閉
- 燈箱說明預設收合 3 行，點一下展開，不讓長文把圖片擠扁
- 橫放手機時說明自動隱藏，整個畫面讓給圖片

## 架構

```
          瀏覽器
             │
   ┌─────────┴─────────┐
   ▼                   ▼
Cloudinary          Supabase
圖片 + CDN           資料庫
────────────        ──────────
存原圖               存文字
自動轉 WebP          title / series
自動壓縮             category / note
全球 CDN             image_url ──┐
                                 │
                 指回 Cloudinary 的網址
```

**為什麼快**：卡片載的是 `w_600,f_auto,q_auto` 的縮圖，不是原圖。
一張 4 MB 的原圖，在卡片上只會載到 40–80 KB。這是 100 多張圖能捲得順的關鍵。

**兩個都沒設定時**：自動進入展示模式，用程式即時產生的 SVG 佔位圖。
所以你可以先把整個網站看完、玩過一輪，再回頭接後端。

## 功能

### 展覽頁

- 響應式 masonry（4 / 3 / 2 / 1 欄）
- **兩層篩選**：分類（chips）+ 作品（下拉選單），兩個是 AND 關係
- 跨欄位搜尋（展品名 / 作品名 / 角色 / 擁有者 / 備註），命中的關鍵字會 highlight
- 排序：最新收錄 / 最早收錄 / 依名稱
- 無限捲動，提前 800px 開始載入
- **隨機看一件**（header 的骰子鈕，或按 R）—— 會在「目前篩選結果的全部」裡抽，
  不是只在已載入的 24 件裡抽；抽中後段的展品會自動先補載資料
- 燈箱：`←` `→` 翻頁、`Esc` 關閉、`Home`/`End` 跳頭尾、點圖放大、底部縮圖膠卷
- 燈箱下方顯示分類與**擁有者**（收錄日期 / 尺寸只在後台看得到，不拿來煩訪客）
- 燈箱翻到底會自動載下一頁（計數顯示 `28 / 48+`）
- 每件展品有專屬網址（`#e=<id>`），可單獨分享
- 鍵盤：`/` 跳到搜尋框、`R` 隨機看一件（燈箱開著時也能按）
- 日 / 夜主題切換，記住選擇
- 尊重系統的「減少動態」設定

### 後台

- 三種登入方式：前端密碼 / **團隊共用密碼（雲端驗證，目前預設）** / 各自 Supabase 帳號
- **擁有者**：登入後設定一次，之後這個瀏覽器上傳的展品自動標記同一個擁有者，
  不用每批重填；隨時可在後台換人
- 拖放上傳、多檔同時、可直接 `Ctrl+V` 貼上截圖
- 每檔獨立進度條，預設帶入檔名當展品名
- 共用欄位（分類 / 作品 / 角色 / 備註）一次套用整批
- 備註是「收藏故事」框架，鼓勵寫長一點（怎麼入手的、保存狀況、想分享的事）
- 已上傳清單：搜尋、編輯（含擁有者）、刪除

## 無障礙

做過一次完整檢查（對比度用程式量、鍵盤操作實測）：

- **色彩對比**全部達到 WCAG AA。日間模式的選中膠囊原本只有 3.2，
  已改用獨立的 `--accent-fill-*` / `--on-accent` token，現在是 4.7–7.0
- **跳過導覽連結**：按第一下 Tab 就能直接跳到展品，不用 Tab 過整個 header
- 26 張圖全部有 `alt`，43 個互動元素全部有可及名稱
- 燈箱是正確的 modal：`role="dialog"` + `aria-modal`、焦點鎖在內部、
  關閉後焦點回到原本的卡片
- 分類篩選是一排 `aria-pressed` 切換鈕（原本誤用了 `role="radio"` 卻沒有 `aria-checked`）
- 尊重系統的「減少動態」設定
- 地標完整（header / main / footer），單一 `h1`，`lang="zh-Hant"`

## 正式上線前的三件事

### 1. 換掉預設密碼

```js
// 瀏覽器 Console 執行
await expoHashPassword('你的新密碼')
// 把印出來的 64 位元字串貼到 config.js 的 adminPasswordHash
```

### 2. 接上 Supabase 和 Cloudinary

照著 **[docs/SETUP.md](docs/SETUP.md)** 走，大約 20 分鐘。

### 3. 決定後台要鎖多緊

| | 前端密碼 | **團隊共用密碼**（目前預設） | 各自 Supabase 帳號 |
|---|---|---|---|
| 設定難度 | 很簡單 | 多 5 分鐘 | 多 5 分鐘 × 人數 |
| 多人上傳 | 可以，但不安全 | ✅ 大家共用一組密碼 | ✅ 每人各自登入 |
| 擋得住懂 F12 的人 | ❌ | ✅ | ✅ |
| 適合 | 純自己收藏、網址不外流 | **團隊一起上傳** | 想知道是誰上傳的 |

> **請認真看這一段。**
> 前端密碼的比對發生在瀏覽器裡，任何人按 F12 就能跳過。
> 而且它搭配的 RLS 政策等於開放資料庫寫入 —— 知道你網址的人可以直接新增或刪除展品。
> **只要這個網址會傳給第三個人，就別用前端密碼。**
>
> 團隊一起上傳的話，用「團隊共用密碼」——密碼雜湊存在 Supabase，
> 比對邏輯在資料庫裡跑，前端看不到判斷式，安全性跟各自帳號一樣，
> 但不用幫每個人開帳號。三種做法的完整設定步驟都在 docs/SETUP.md 第三節。

## 已知的取捨

誠實列出來，免得你之後踩到覺得是 bug：

1. **沒有用 Tailwind CSS**
   原規劃是 Tailwind，但我改用了手寫的 CSS 設計系統。
   原因：這個站的視覺（ADV 對話框、選択肢按鈕、晝夜配色）靠 utility class 寫不出來，
   最後還是得寫大量自訂 CSS；而 Tailwind Play CDN 會多載 100KB+ 的執行期編譯器並造成閃爍，
   要走建置流程又跟「零建置、存檔即生效」的目標衝突。
   目前是約 56KB 的單一 CSS 檔，用 CSS 變數做設計 token。
   如果你還是想要 Tailwind，跟我說，我可以改。

2. **刪除展品不會刪掉 Cloudinary 上的圖**
   只移除資料庫紀錄。免費方案 25GB 空間很夠用，要清就到 Cloudinary Media Library 手動刪。

3. **每件展品只能有一張圖**
   週邊其實很需要看背面和細節。三種做法的評估寫在
   [docs/DESIGN-multi-image.md](docs/DESIGN-multi-image.md) —— 但我的建議是**先別做**，
   等你上傳完第一批真實照片，才知道到底需不需要。

4. **立繪、logo、圖示全是佔位圖**
   替換清單在 [docs/ASSETS.md](docs/ASSETS.md)。

5. **隨機背景（v2）已經做好，但預設關閉**
   程式在 `assets/js/background.js`。它只在圖片存在 Cloudinary 時才會啟用，
   因為需要伺服器端先把圖模糊好 —— 實測用瀏覽器的 CSS 做全螢幕模糊會讓分頁卡死十幾秒。
   等你上傳真實照片後，把 `config.js` 的 `ux.randomBackground` 改成 `'exhibits'` 即可。

## 接下來

[docs/ROADMAP-v2.md](docs/ROADMAP-v2.md) 有完整規劃與實測筆記。

我的建議順序：

1. **上傳真實的週邊照片** —— 佔畫面 95% 的面積，影響遠大於其他任何一項
2. **作品篩選**（待做，你要求的）—— 篩選列多一欄可以只看同一部作品的展品，
   規劃寫在 [docs/ROADMAP-v2.md](docs/ROADMAP-v2.md#待做作品篩選)
3. **打開隨機背景看看** —— 照片一上去就可以把 `ux.randomBackground` 改成 `'exhibits'`，
   花 10 秒判斷用展品照當背景好不好看。不喜歡再考慮做專屬的背景圖庫
4. **展品支援多張圖** —— 週邊很需要看背面和細節，這是我覺得功能面最值得補的
5. **重做 OG image** —— 現在那張是純文字排版，等有真實照片後換成拼貼版會更吸引人
